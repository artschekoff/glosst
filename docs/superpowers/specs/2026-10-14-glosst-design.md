# Glosst — перевод по наведению. Дизайн

**Имя.** Gloss + ghost. *Глосса* — филологический термин ровно для того,
что здесь делается: перевод трудного слова, надписанный над строкой в
рукописи. *Ghost* — потому что расширение проходит по странице
призраком: разметка после него побайтово та же, что была.

**Что это.** Расширение Chrome для чтения в оригинале. Страница остаётся
нетронутой; когда курсор задерживается на непонятном месте, появляется
тултип с переводом этого места и короткой пометкой о грамматике.

**Для кого.** Один пользователь, учит испанский, живёт в Аргентине.
Основная пара — испанский → русский, остальные пары настройкой.

**Главный принцип.** Перевод только по требованию. Пока человек просто
читает, расширение не тратит ни токена и не делает ни запроса. Это не
оптимизация, а требование: заранее переведённый текст человек всё равно
не прочитает, а деньги за него уже заплачены.

---

## Почему не «обернуть текст в теги»

Обычный путь таких расширений — пройти страницу, разрезать текстовые
узлы и завернуть каждое предложение в `<span>`. От этого отказываемся:

- мы переписываем DOM чужого сайта. React и Vue при следующей
  перерисовке либо снесут обёртку, либо упадут;
- ломаются селекторы вида `:nth-child`, едет вёрстка;
- на бесконечной прокрутке нужен `MutationObserver` и постоянная
  переобработка;
- и главное — это работа по всей странице заранее, то есть прямо против
  принципа «по требованию».

Вместо этого страница не меняется вообще. Всё нужное считается в момент
наведения по трём браузерным механизмам (проверены в Chrome 151):

| Механизм | Что делает | Проверка |
|---|---|---|
| `document.caretRangeFromPoint(x, y)` | по точке на экране даёт текстовый узел и смещение в нём | вернул смещение 9 в нужном `#text` |
| `Intl.Segmenter(lang, {granularity:'sentence'})` | режет текст на предложения с учётом языка | `Vino a casa muy tarde, porque el tren se retrasó. Luego cenamos juntos.` → ровно 2 предложения |
| CSS Custom Highlight API (`Highlight`, `CSS.highlights`) | подсвечивает диапазон, не меняя разметку | подсветка выставилась, DOM без изменений |

Своих регулярок для нарезки не пишем: `Intl.Segmenter` знает правила
конкретного языка, а регулярка по точкам и запятым ломается на первом же
`1.500`.

**Но одну его слабость закрываем руками.** Проверка показала: числа
(`Cuesta 1.500 pesos.`) и многоточия (`No sé... quizá mañana.`) он режет
верно, а на сокращении с точкой — нет. `Sr. García llegó tarde.` он
делит на `Sr. ` и `García llegó tarde. `, и наведение на имя дало бы
единицей огрызок `Sr. ` — для перевода бесполезный и ещё и платный.

Поэтому поверх сегментера идёт один проход: кусок, оканчивающийся
известным сокращением (`Sr.`, `Sra.`, `Dr.`, `Av.`, `Lic.`, `etc.` и
подобные), склеивается со следующим. Список — по языку, рядом с кодом
нарезки. С этим проходом все проверенные случаи режутся верно:

| Вход | Результат |
|---|---|
| `Sr. García llegó tarde. Cenamos juntos.` | `Sr. García llegó tarde.` + `Cenamos juntos.` |
| `Vive en Av. Corrientes. Trabaja cerca.` | `Vive en Av. Corrientes.` + `Trabaja cerca.` |
| `Cuesta 1.500 pesos. Es barato.` | `Cuesta 1.500 pesos.` + `Es barato.` |
| `No sé... quizá mañana. Ya veremos.` | `No sé... quizá mañana.` + `Ya veremos.` |
| `Hola mundo` (без точки) | `Hola mundo` |

Список сокращений заведомо неполон, и это приемлемо: промах даёт
короткую единицу, а не сломанную страницу. Пополняется по мере того, как
такие места попадаются.

`MutationObserver` не нужен вовсе: мы смотрим на страницу в момент
наведения, а не держим её слепок.

## Как это работает

```
курсор замер (~300 мс)
   │
   ├─ caretRangeFromPoint → текстовый узел + смещение
   ├─ выбор единицы по режиму:
   │     предложение → Intl.Segmenter по тексту ближайшего блока
   │     абзац       → текст блочного элемента целиком
   ├─ Range на эту единицу → подсветка (CSS.highlights)
   │
   └─ фоновому воркеру: {текст, язык-источник, язык-цель, модель}
          │
          ├─ кэш по хэшу → попадание? вернуть сразу
          └─ промах → запрос к модели → в кэш → вернуть
   │
   └─ тултип в shadow DOM: перевод + пометка
```

Подсветка показывается только под курсором. Страница при чтении
выглядит нетронутой, светится лишь то, на что человек смотрит.
Предварительная разметка всех единиц сознательно не делается: она
требует сканирования страницы заранее и возвращает нас к тому, от чего
ушли.

### Режимы

| Режим | Единица | Когда удобен |
|---|---|---|
| Предложение (по умолчанию) | предложение внутри блока | обычное чтение, непонятно одно место |
| Абзац | текст блочного элемента | плотный текст, проще взять кусок целиком |

Режим переключается в настройках. В абзацном режиме
за один вызов уходит больше текста — вызовов меньше, каждый дороже.

### Чем вызывать

Два условия сразу: **зажата клавиша-модификатор** (по умолчанию Alt) и
курсор простоял на месте ~300 мс. Клавиша настраивается, в том числе
отключается совсем.

Модификатор здесь не украшение. Без него тултипы выскакивали бы при
обычном чтении — курсор почти всегда лежит где-то в тексте, и каждая
пауза в чтении оборачивалась бы всплывающим окном. С Alt расширение
молчит, пока его не позовут.

Задержка нужна и при зажатой клавише: иначе проводка мышью через абзац
с зажатым Alt выстрелила бы десятком запросов.

Важная мелочь: клавишу можно зажать, не двигая мышью. Значит отсчёт
запускается не только движением, но и нажатием модификатора — по
последней известной позиции курсора. Иначе пришлось бы дёргать мышь,
чтобы расширение заметило нажатие. Отпустили клавишу — подсказка
убирается, отсчёт сбрасывается.

### Язык страницы

Язык нужен нарезке: `Intl.Segmenter` режет по правилам конкретного
языка.

Берём из `<html lang>`. Если атрибута нет — **спрашиваем, а не
угадываем**. Угадывание здесь хуже отказа: ошиблись языком, нарезка
поехала, и человек получил кривую единицу, не понимая почему.

Вопрос задаётся один раз на сайт: вместо перевода тултип показывает
короткий список языков, выбор запоминается для этого домена. Дальше
сайт работает молча.

Выбор хранится отдельно от кэша переводов, ключом по домену, и
сбрасывается кнопкой в настройках.

### Цвета и состояния

Подсветка несёт состояние, а не просто отмечает место. CSS Custom
Highlight API позволяет держать несколько именованных слоёв
одновременно, у каждого своё оформление и свой приоритет при наложении.
Проверено в Chrome 151: три слоя сосуществуют, `priority` разрешает
перекрытие, снятие одного не трогает остальные, разметка страницы
остаётся побайтово прежней.

| Состояние | Вид | Смысл |
|---|---|---|
| Под курсором, перевод запрошен | жёлтый фон | «взял в работу» |
| Перевод показан | жёлтый фон, тултип рядом | читаемое сейчас место |
| Уже переведено в этом сеансе | бледно-зелёный фон, подчёркивание | след прочитанного: видно, что уже разбирал |
| Ошибка | бледно-красный фон | перевод не получился, причина в тултипе |

Слой «уже переведено» живёт, пока открыта страница, и даёт след по
тексту: с одного взгляда видно, какие места уже разбирались, а какие
пропущены. При наложении активный слой перекрывает след — приоритет
у него выше.

Цвета настраиваются: на тёмных темах и на цветных фонах умолчания могут
читаться плохо, а подсветка, которую не видно, бесполезна.

Границы слоя «уже переведено» привязаны к `Range`, то есть к текущему
состоянию DOM. При переходе внутри SPA разметка меняется и след
сбрасывается — это правильное поведение: текст уже другой.

## Устройство

Расширение Manifest V3. Разделено по ответственностям, каждый файл можно
читать и проверять отдельно.

### Контент-скрипт — всё, что касается страницы

| Файл | Ответственность |
|---|---|
| `src/content/hover.js` | задержка курсора, точка → `Range`; больше ничего не знает |
| `src/content/segment.js` | текст + смещение + режим → границы единицы. Чистая функция, без DOM |
| `src/content/highlight.js` | слои подсветки поверх CSS Custom Highlight API: активный, след, ошибка; приоритет при наложении |
| `src/content/tooltip.js` | тултип в shadow DOM: позиция, состояния «ищу» / перевод / ошибка |
| `src/content/index.js` | связывает перечисленное, общается с воркером |

Контент-скрипт **никогда не видит ключ API** и не ходит в сеть.

### Фоновый воркер — всё, что касается денег и сети

| Файл | Ответственность |
|---|---|
| `src/bg/translate.js` | сборка запроса, разбор ответа, ошибки |
| `src/bg/cache.js` | чтение/запись/срок жизни |
| `src/bg/settings.js` | чтение настроек с умолчаниями |
| `src/bg/index.js` | приём сообщений, порядок «кэш → сеть → кэш» |

### Настройки

`src/options/` — страница настроек.

| Настройка | Умолчание |
|---|---|
| Ключ API | пусто (без него расширение честно говорит, что не настроено) |
| Модель | `gpt-4o-mini` |
| Язык цели | русский |
| Язык источника | из `<html lang>`, иначе спросить |
| Режим | предложение |
| Клавиша вызова | Alt (можно сменить или отключить) |
| Задержка | 300 мс |
| Срок жизни кэша | 30 дней |
| Пометки о грамматике | включены |
| Работать на этом сайте | включено везде (см. открытый вопрос 4) |

Модель — список с возможностью вписать своё: провайдеры меняют названия
чаще, чем выходят версии расширения. Первой и по умолчанию идёт
`gpt-4o-mini`. Слой провайдера отделён от остального (`translate.js`),
так что добавить другого — одна функция, а не переделка.

## Хранилище и кэш

Хранилище — `chrome.storage.local` с разрешением `unlimitedStorage`.

`localStorage` не годится принципиально: контент-скрипт видит
`localStorage` **той страницы, где сидит**. Кэш размазался бы по чужим
сайтам, на каждом свой, с лимитом около 5 МБ и без возможности
почистить его одним действием.

**Ключ записи** — хэш от `текст + язык-цель + модель`, а не от URL. Одна
и та же фраза на разных страницах переводится один раз. Модель в ключе
обязательна: сменили модель — прежние переводы не выдаются за новые.

**Запись:** `{ translation, note, ts, model }`.

**Срок жизни** 30 дней, настраивается. Просроченное отбрасывается при
чтении; раз в сутки по `chrome.alarms` подчищается всё разом. Если
хранилище подошло к пределу — удаляются самые старые записи.

## Запрос к модели

Одно обращение на единицу текста. Просим перевод и, если включено,
короткую пометку о том, что в этом месте можно не понять: форма глагола,
идиома, местный аргентинский оборот.

Ответ — строгий JSON (`response_format: json_object`), иначе разбор
ответа превращается в угадывание:

```json
{ "translation": "Пришёл домой очень поздно, потому что поезд задержался.",
  "note": "vino — не «вино», а pretérito от venir (прийти)" }
```

Поле `note` необязательное: модель возвращает его, когда есть что
сказать, и опускает, когда место простое. Пустую пометку в тултипе не
показываем.

Язык источника по умолчанию определяет модель сама — отдельный вызов на
определение языка удваивал бы и задержку, и стоимость.

## Ошибки

Тултип всегда говорит, что произошло. Молчаливый провал здесь худшее из
поведений: человек ждёт перевод и не понимает, сломалось оно или думает.

| Что случилось | Что видно в тултипе |
|---|---|
| Ключ не задан | «Не задан ключ API — откройте настройки» со ссылкой |
| 401 | «Ключ не принят» |
| 429 / `insufficient_quota` | «Закончился баланс или лимит запросов». Это разные вещи, и отличать их важно: у OpenAI пустой баланс приходит как 429, и выглядит как «слишком много запросов», хотя лечится пополнением |
| Сеть недоступна | одна повторная попытка, затем «нет связи» |
| Ответ не разобрался | «Неожиданный ответ модели», текст — в консоль |

## Проверка

Три уровня, каждый проверяет своё.

**Чистые функции — обычные юнит-тесты, без браузера.** Нарезка на
единицы (`segment.js`), ключ кэша, срок жизни, сборка запроса, разбор
ответа, разбор ошибок. Сюда же случаи, которые ломают регулярки:
`Sr. García`, `1.500 pesos`, многоточие, текст без финальной точки.

**Поведение на странице — Playwright.** Chromium на этой машине уже
работает. Проверяется: наведение подсвечивает именно то предложение, в
котором стоит курсор; проводка мышью без остановки не вызывает запроса;
разметка страницы после наведения побайтово та же, что до (ровно та
гарантия, ради которой выбран вариант B); тултип не наследует CSS сайта.
Переводчик при этом подменён заглушкой — тесты не ходят в сеть и не
тратят деньги.

**Живой вызов — один тест, по флагу.** Проверяет, что запрос и разбор
ответа сходятся с настоящим API. По умолчанию выключен.

## Что сознательно не делаем

- Не переводим всю страницу — против основного принципа.
- Не делаем словарь, повторение и карточки. Это отдельный инструмент;
  если понадобится — отдельный проект поверх кэша.
- Не поддерживаем Firefox и Safari: выбранные механизмы подсветки и
  `caretRangeFromPoint` работают не везде. Решение осознанное, в пользу
  простоты.
- Не делаем свой сервер-прокси. Ключ лежит в хранилище расширения;
  для личного инструмента этого достаточно (см. открытый вопрос 6).

## Решённые вопросы

Задавались по ходу проектирования, ответы владельца внесены в дизайн
выше.

| Вопрос | Решение |
|---|---|
| Подсветка: только под курсором или разметить всё заранее? | Только под курсором, плюс след уже переведённого |
| Чем вызывать: хватает задержки или нужна клавиша? | Зажатый Alt плюс задержка. Клавиша настраивается |
| Пометки о грамматике по умолчанию? | Включены — ради учёбы в них весь смысл |
| Где работать: везде или по списку сайтов? | Везде |
| Язык цели — всегда русский? | Русский по умолчанию, меняется в настройках |
| Язык страницы, если нет `<html lang>`? | Спросить один раз на домен и запомнить. Не угадывать |
| Ключ в хранилище расширения — устраивает? | Да, для личного инструмента достаточно |
